- 전략 ID / 이름: rs-momentum / 상대강도 모멘텀 상위 3 (국면 필터)
- 버전: v4 (규칙·파라미터 변경 시 +1, 이전 검증 결과 승계 없음 — D-011)
- 설명: 유니버스 안에서 mom_n 거래일 수익률 순위 상위 3종목을 보유한다. 순위가 exit_rank 밖으로 밀리거나 종가가 SMA(trend_n) 이하면 청산한다. 청산 뒤 reentry_wait 확정 일봉 동안 같은 종목에 재진입하지 않는다(SMA 경계 진동 왕복 억제). 보유 3종목 한도(L6)를 전략이 직접 채워 종목코드 순서 편향을 없앤다.
- 상태(시장별): M1 초안(전략실 연구). 운영 등록 없음
- 대상 시장: M1
- 유니버스 방식: U-A 고정 목록 — 출처: 전략실 `data\daily`(2026-10-11부터 **코스피200 현재 구성 200종목**, 운영 ka10081 사본 — 현재 구성이라 **사후 선택**; v1~v3는 시총 상위 30). 순위는 그날 평가 가능한 종목(워밍업·품질 통과) 안에서만. 지수 종목 `KOSPI`는 국면 입력만, 거래·순위·보유 집계에서 제외.
- 보유 기간: 수주~수개월 예상 / 최대 보유 제한 없음(순위·추세 이탈로 청산)

## 규칙 표 (§2.2)
우선순위 필드는 같은 종류 규칙끼리의 순서만 정한다. 종류 간 순서는 청산 > 감액 > 증액 > 진입으로 고정(D-006).

| 규칙 ID | 종류 | 입력 | 판정 시점 | 조건 | 행동 | 무효 조건 | 우선순위 |
|---|---|---|---|---|---|---|---|
| EXIT-1 | EXIT | CAP-DAT-01·상태 입력 | 09:30 | 보유 AND (mom_n 수익률 순위 > exit_rank OR 종가 <= SMA(trend_n)) | 전량 시장가 청산 | 데이터 품질 실패·처리 중 주문 | 1 |
| REENTRY-1 | REENTRY_BLOCK | 상태 입력(직전 청산 시각) | 09:30 | 직전 청산(사유 무관) 있음 AND 청산일(KST) 뒤 확정 일봉 수 < reentry_wait | ENTRY-1 신호를 내지 않음 | — | 1 |
| REGIME-1 | REENTRY_BLOCK | CAP-DAT-01(지수 KOSPI 일봉) | 09:30 | 지수(KOSPI) 전일 종가 <= SMA(regime_n) OR 지수 데이터 없음·봉 부족 | ENTRY-1 신호를 내지 않음(청산·보유는 영향 없음) | — | 2 |
| ENTRY-1 | ENTRY | CAP-DAT-01·상태 입력 | 09:30 | 전략 보유 종목 수 < 3 AND 미보유 AND REENTRY-1 아님 AND 순위 <= 3 AND mom_n 수익률 > 0 AND 종가 > SMA(trend_n) — 순위 순으로 빈 슬롯 수(3 − 보유)만큼만 | S-3 시장가 진입, 손절가 = 종가 − atr_mult×ATR14 | 데이터 품질 실패·거래 상태 이상·처리 중 주문 | 1 |

- 순위: 평가 가능 종목의 mom_n 수익률 내림차순, 같은 값은 종목코드 순(결정적).
- 당일 청산으로 비는 슬롯은 다음 판정에 채운다(보수적 — 같은 날 교체 없음).
- 보유 수는 전략 소유 포지션 전체로 센다(품질 실패로 평가 불가인 보유 종목도 슬롯을 차지).

## 파라미터 (R-19, 값은 config/strategies/)
| 이름 | 타입 | 단위 | 허용 범위 | 설명 |
|---|---|---|---|---|
| mom_n | int | 거래일 | 60~250 | 수익률 측정 기간(초기값 120, 약 6개월) |
| trend_n | int | 거래일 | 50~200 | 추세 필터 SMA 기간(초기값 100) |
| exit_rank | int | 순위 | 4~15 | 이 순위 밖이면 청산(초기값 6, > 3 필수) |
| reentry_wait | int | 거래일 | 0~40 | 청산 뒤 재진입 대기 확정 일봉 수(v3 기본 0 = 없음; v2의 10은 개선 아님) [v2] |
| regime_n | int | 거래일 | 0~250 | 국면 필터 지수 SMA 기간(초기값 200, 0 = 필터 없음 = v3 규칙) [v4] |
| order_cap | decimal | 원 | 100,000~1,000,000 | 1회 주문 금액 상한(상한가 기준 환산). 상한 = 계좌 L7(넘으면 게이트 전부 거부 → ±20% 변형은 경계값) [v3, v4에서 상한 L7로] |
| atr_mult | decimal | 배 | 1~5 | 크기 계산용 손절 ATR 배수(초기값 2) |
| risk_ratio | decimal | 비율 | 0.001~0.005 | 1회 위험 = 기준 금액 × 값(초기값 0.004, L1 이하) |
| max_weight | decimal | 비율 | 0.01~0.10 | 종목 비중 상한(초기값 0.09, L2 이하) |
- 상수: TOP_N = 3(계좌 L6과 같음 — L6 변경 시 버전 +1). 수치 파라미터 9개 → ±20% 변형 18개(C-4). 이 중 atr_mult·risk_ratio·max_weight·order_cap(+는 경계값, −는 80만으로 실제 변형)·reentry_wait(0 ± 20% = 0)는 "결과 동일"이 많아 유효 변형은 약 7~9개 예상.
