## 사전 등록 (v1, 2026-10-09) — 실행 뒤 변경 금지
- 가설: 대형주 유니버스 안에서 6개월 상대 수익률 상위 종목이 이후 수주~수개월 동안 상대적으로 계속 앞선다(횡단면 모멘텀). 보유 3종목 한도를 전략이 순위로 직접 채워 종목코드 순서 편향을 없앤다. 근거는 일반 문헌이며 **이 데이터에서의 실증은 없다**(ideas/2026-10-09-rs-momentum.md).
- 파라미터 초기값·근거: mom_n 120(6개월 표준), trend_n 100(mom_n보다 짧은 추세 필터), exit_rank 6(=2×보유 3, 히스테리시스), atr_mult 2(견본과 같음), risk_ratio 0.004·max_weight 0.09(계좌 한도 이하 공통값). 데이터를 보고 고르지 않았다.
- 폐기 기준:
  - 1차 선별(quick, 창 4·7 합산): 거래당 기대값 ≤ 0 **또는** 거래 < 10건 → 폐기.
  - 미리 돌려 보기(validate): 판정 "미충족"·"판단 불가" → 폐기 또는 v+1(바꿀 것 한 가지와 이유를 적고, 시도 상한 안에서).
- 시도 상한: v1 5회(trials.jsonl 기준, 라벨 불문). 초과 시 폐기 또는 사용자 결정.
- critic 검토(2026-10-09, 실행 전): 차단 0 / 비차단 7. 실행 전 반영 사항 — ① L7 100만 원(상한가 기준 ≈77만 원)이 크기를 지배하므로 `risk_ratio`·`max_weight` ±20% 변형은 기준과 같은 결과가 날 것 → C-4 **유효 변형 8개**로 해석, 판단은 거래당 기대값과 벤치마크(동일 비중) 초과분으로만 ② SMA(trend_n) 이탈↔재진입 쿨다운 없음 → 결과에서 **보유일 ≤ 5 왕복 비율**을 반드시 집계(높으면 v2에서 쿨다운 검토, v1은 그대로) ③ 상위 3이 모두 보유·탈락이면 빈 슬롯이 오래 비어 거래 수가 줄 수 있음 → C-2 미달 원인 분석용으로 기록.
- 기대 거래 수(추정, 확인 아님): 보유 3 × 연 2~4회 교체 ≈ 창당 6~12건 → 7개 창 합산 ≥ 100(C-2)은 **미달 가능성이 있다**. C-2 미달이면 "판단 불가"로 끝날 수 있음을 미리 적어 둔다.

## 사전 등록 (v2, 2026-10-10) — 실행 뒤 변경 금지
- v1 → v2 변경 **한 가지**: REENTRY-1(REENTRY_BLOCK) 추가 — 직전 청산일(KST) 뒤 확정 일봉 수 < `reentry_wait`이면 그 종목 진입 금지(운영 trend-sma의 REENTRY-1과 같은 정의). 다른 규칙·값은 v1과 동일.
- 이유(v1 validate 결과에서): 보유 ≤ 5일 왕복 34건(24%)이 7개 창 전부 손실(−766,427원) — SMA(trend_n) 경계 진동으로 청산 다음 날 재진입하는 왕복. 쿨다운은 이 경로만 막는다(순위·추세 조건은 그대로).
- `reentry_wait` 초기값 10(허용 0~40): 문제 왕복의 보유일(≤5)의 2배. v1 데이터의 재진입 간격 분포를 보고 고른 값이 아니라 사전에 정한 값이다(검증 창 데이터로 조정하지 않음).
- 예상되는 부작용(미리 적음): 거래 수 감소(143 → C-2 100 미달 가능), 쿨다운 중 순위 1~3 종목을 놓쳐 슬롯이 비는 날 증가.
- 폐기 기준(v1과 같음): quick 창 4·7 합산 기대값 ≤ 0 또는 < 10건 → 폐기. validate 미충족·판단 불가 → 폐기 또는 사용자 결정. **v2 판단 기준 추가**: v1 대비 창별 양수 기대값 창 수가 늘지 않으면(3/7 유지·감소) v2는 개선 아님 → v1·v2 모두 "보류"로 사용자에게 올림.
- 시도 상한: v2 5회.

## 사전 등록 (v3 · 규모 실험, 2026-10-11) — 실행 뒤 변경 금지
- 사용자 지시: "제안대로 해, 전략을 연구할 때 좋고 유리한 방향으로" (L7 100만 원이 크기를 지배하는 문제).
- v3 변경: `order_cap` 파라미터 추가(상수 100만 → 파라미터), `reentry_wait` 기본 0(v1 규칙). **규칙 변화 없음** — 기본값(cap 100만, wait 0)이면 v1과 결과가 같아야 한다 → 대조 실행으로 확인(다르면 v3 코드 오류).
- 실험 설계(전략 우위 판정이 아니라 **환경 측정**): 전략실 한도 사본으로 quick 창 4·7.
  - A `limits-scale-test.toml`(L7 1,000만, 나머지 운영값) + `order_cap` 1,000만 → 예상: 게이트 L1(상한가 − 손절가 기준)이 진입 대부분 거부(운영 trend-sma 실험과 같은 현상). 측정값: L1 거부 수.
  - B `limits-scale-test-l1fix.toml`(A + L1 2% 임시 보정) + `order_cap` 1,000만 → "L1 계산 정합(운영 CP) 뒤"의 근사. 측정값: 거래 수·거래당 기대값·투자 비중. 이 결과는 **사용자 미결정 한도 가정**이며 v1 결과와 직접 비교하지 않는다(크기가 다르면 기대값 원 단위가 커지는 것은 당연 — 거래당 기대값을 **진입 금액 대비 %** 로도 본다).
- 판단 기준: A에서 L1 거부가 진입 신호의 과반이면 "운영 L1 계산 정합 CP 필요"를 수치 근거로 기록. B에서 창 4·7 거래 수가 v1(28·16)과 비슷하고 기대값(%)이 v1과 같은 부호면 "규모 확대로 전략 성격 불변" 기록. 폐기 판정은 하지 않는다(규모 실험).
- 시도 장부: 규모 실험 3회(대조·A·B)는 v3 시도로 기록되지만 파라미터 탐색이 아니다.
