# /read-results — 결과 읽기와 결론 기록

입력: `$ARGUMENTS` = 결과 폴더 경로(`results/<날짜>-<후보>` 또는 `results/quick/<폴더>`). 없으면 `results/`에서 가장 최근 폴더를 골라 어느 것인지 먼저 말한다.

## validate 결과(`…/<ID>-v<n>/validation-v<n>.md`, `verdict.json`)
1. 판정표(C-1~C-8)를 **그대로** 옮긴다: 판정(통과 / 통과(과대 추정 가능) / 미충족 / 판단 불가)과 사유 줄. 수치를 고쳐 말하지 않는다.
2. 창별 결과 표에서: 손실 창 수, 기대값이 음수인 창, 거래 수가 5건 미만인 창(표본 부족), 미청산 수를 적는다.
3. 파라미터 ±20% 표에서: "결과 동일(한도에 묶임 가능)" 변형은 **시험되지 않은 것**으로 간주하고 개수를 적는다. 어떤 파라미터에 민감한지 한 줄.
4. 단순 보유 비교는 투자 비중 차이 때문에 수익률을 그대로 비교하지 않는다(판정표 주석 그대로).
5. 실행 조건에서 운영 코드 커밋·호가 표 여부·슬리피지·비용을 적는다(다른 실행과 비교 가능 여부).

## quick 결과(`results/quick/<폴더>/w<k>-<라벨>/summary.json`, `candidates/<후보>/trials.jsonl`)
- 창별 거래 수·거래당 기대값·거부(G7 등) 수·품질 실패 수. `trials.jsonl` 누적 횟수를 적고 사전 등록의 시도 상한과 비교한다.
- 거부 수가 신호 수의 대부분이면(예: G7 자금·한도) "한도가 결과를 지배 — 전략 우위 판단 불가"라고 적는다.

## 결론 기록
`candidates/<후보>/notes.md` 기록 절에 두 줄을 **추가**한다(기존 줄 수정 금지):
- `<날짜> v<n> <도구>: 판정 … / 핵심 수치 … / 운영 커밋 …`
- `결론: 폐기 | 보류(이유) | v+1(바꿀 것 한 가지와 이유) | 인계 요청(/handoff)` — 사전 등록의 폐기 기준에 걸리면 **폐기**가 기본값이다. 기준을 넘지 못했는데 계속하려면 사용자 결정으로 표시한다.
- 한계 문장(생존편향·과대 추정·비용 가정)을 붙인다.

## 보고
판정·사유·결론·다음 행동을 10줄 이내로. 결과 파일에 없는 수치를 만들지 않는다.
